# Back best practices audit

Audit of `back/` against [`best-practices.md`](best-practices.md), 2026-11-01.
Severity: **bug**, **security**, **perf**, **readability**. Status: **fix** (done in
this branch) or **later** (left on purpose, reason given).

## Bootstrap and lifecycle — `main.ts`, `app.module.ts`

| Gap                                                                                                                                                        | Rule                                   | Planned fix                                                                                                                                                              | Severity    | Status                                 |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------- | -------------------------------------- |
| `enableShutdownHooks()` is never called, so SIGTERM skips `onModuleDestroy`: the Postgres pool is never closed and the reminder cron keeps the loop alive. | NestJS: shutdown hooks                 | Call `app.enableShutdownHooks()` before listening.                                                                                                                       | bug         | fix                                    |
| `void bootstrap()` has no `catch`: a boot failure is an unhandled rejection with no context.                                                               | Node: bootstrap failures               | Catch, log through `Logger`, `process.exit(1)`.                                                                                                                          | readability | fix                                    |
| `PORT` is read from `process.env`, not `ConfigService`.                                                                                                    | NestJS: config through `ConfigService` | Read it from `ConfigService`.                                                                                                                                            | readability | fix                                    |
| No health endpoint; the Docker healthcheck probes `/graphql`.                                                                                              | Observability: health endpoint         | Add `GET /health` (pings the database).                                                                                                                                  | readability | fix                                    |
| No `trustProxy`: behind Cloudflare / Passenger every request has the proxy IP.                                                                             | Security: real client IP               | Throttler keys on `cf-connecting-ip` when present (see Security). `trustProxy` itself also changes `req.protocol` (image URLs), so it needs a check in production first. | security    | fix (throttler) / later (`trustProxy`) |
| Body size relies on Fastify's default (1 MiB); multipart is capped at 5 MB.                                                                                | Security: body size capped             | Already capped by default; a tighter limit needs the worker payload sizes measured first.                                                                                | security    | later                                  |

## Security — auth and rate limiting

| Gap                                                                                                                                                                                                          | Rule                                    | Planned fix                                                                                                       | Severity | Status |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------- | ------ |
| `/auth/login`, `/auth/register`, `/auth/forgot-password`, `/auth/resend-verification`, `/auth/verify-email`, `/auth/reset-password` have no rate limit: password brute force and mail flooding are possible. | Security: auth rate limited             | `ThrottlerGuard` with a tight `@Throttle` (10/min per route and client) on the auth controller.                   | security | fix    |
| The throttler keys on `req.ip`, which is the proxy IP in production: the recognition enqueue limit (20/min) is shared by every user.                                                                         | Security: real client IP                | Throttler `getTracker` keyed on `cf-connecting-ip`, falling back to `req.ip`.                                     | bug      | fix    |
| `POST /worker/pair/start` and `/worker/pair/poll` take inline body types, so the `ValidationPipe` validates nothing: `poll` with no `secret` crashes in `hash(undefined)` and answers 500.                   | NestJS: every body is a validated class | `StartPairingInput` / `PollPairingInput` classes; a missing secret is a 400.                                      | bug      | fix    |
| The Pl@ntNet API key is concatenated into the URL without encoding.                                                                                                                                          | Node: secrets not in URL strings        | Pass it through axios `params`.                                                                                   | security | fix    |
| JWT secret: required (`getOrThrow`) but its strength is not checked.                                                                                                                                         | Security: JWT secret                    | A length check at boot would reject the compose default `dev-jwt-secret-change-in-prod`, used by the local stack. | security | later  |

## Node — async and outbound calls

| Gap                                                                                                                                                                           | Rule                                          | Planned fix                                                        | Severity    | Status |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------ | ----------- | ------ |
| The reminder cron runs `onTick: () => void this.runOnce()` with no `catch`: a database error during the tick is an unhandled rejection, which kills the process on Node ≥ 15. | Node: background task never rejects unhandled | Catch and log inside the tick.                                     | bug         | fix    |
| `sendDueReminders` uses `Promise.all`: one user whose push or query fails rejects the whole round.                                                                            | Node: one failure does not abort a batch      | `Promise.allSettled`, failed users logged.                         | bug         | fix    |
| `AiService.embed` and the GBIF calls have no timeout: a hung embedder or GBIF stalls the request (or the sweep) forever.                                                      | Node: timeout on every outbound call          | `HttpModule.register({ timeout })` in the AI and taxonomy modules. | bug         | fix    |
| `no-floating-promises` and `no-unsafe-argument` are warnings, `no-explicit-any` is off (the code is already clean).                                                           | TypeScript / Node: lint as errors             | Turn them into errors so they stay clean.                          | readability | fix    |
